LAB CASE STUDY

Investigating a Suspicious Microsoft Sign-in Email

I reviewed a simulated phishing alert, examined the sender and embedded URL, then searched firewall telemetry in Splunk to determine whether the destination connection was allowed.

Alert ID 8817
Incident type Phishing
Severity Medium
Firewall result Connection allowed

INVESTIGATION WALKTHROUGH

Evidence & Analysis

Select any image to open the full-size screenshot.

01 / EMAIL REVIEW

Review the suspicious email

The message impersonated Microsoft and used no-reply@m1crosoftsupport.co. The number “1” replaces the letter “i” in the brand name, a typosquatting indicator. The email contained a sign-in link to the same suspicious domain.

02 / SIEM INVESTIGATION

Search firewall logs in Splunk

I searched for the suspicious URL and identified a matching firewall event. The event showed traffic from 10.20.2.25 to 45.148.10.131 over TCP port 443, with the action recorded as allowed.

Open full image ↗
03 / REPORTING

Document findings and response

I classified the alert as a true positive and documented the supporting indicators. Response actions included blocking the malicious URL, domain, and destination IP, reviewing sign-in activity, and resetting credentials if the user had submitted them.

04 / LAB RESULTS

Review classification accuracy

The lab dashboard recorded a 100% true-positive identification rate and a 100% false-positive identification rate for the alert types shown in this exercise.

WHAT I PRACTICED

Key takeaways

  • Identifying typosquatting and brand-impersonation indicators in email.
  • Searching SIEM data for URL and firewall activity.
  • Interpreting connection actions, source and destination IPs, and ports.
  • Writing evidence-based incident classifications and remediation steps.

Note: This is a training-lab exercise using simulated security data. It is presented as practical learning evidence, not as production incident-response experience.
